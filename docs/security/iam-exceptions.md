# IAM exceptions

Actions below cannot be scoped to a resource ARN, or are waiting on a later ticket to name the ARN. A `*` inside an ARN is listed too. Each one is limited to the role that needs it.

| Action | Role | Why |
| --- | --- | --- |
| `xray:PutTraceSegments`, `xray:PutTelemetryRecords` | `PreTokenFunctionRole`, `TenantIdAttributeFunctionRole` | X-Ray rejects resource-level permissions. `tracing=ACTIVE` on those functions adds both actions with `Resource: *`. |
| `xray:PutTraceSegments`, `xray:PutTelemetryRecords` | `ChannelRouterFunctionRole`, `DeviceSeedFunctionRole`, `EvidenceAnalyzerFunctionRole`, `ReportGeneratorFunctionRole`, `WsHandlerFunctionRole`, `WsAuthorizerFunctionRole`, `StreamBroadcasterFunctionRole`, `ActionHandlerFunctionRole`, `InboundFunctionRole`, `IngestFunctionRole` | `tracing=ACTIVE` on every compute function adds both actions with `Resource: *`. X-Ray rejects a resource ARN. `DeviceSeedFunctionRole` is the always-on `oerf-device-seed` provider. |
| `s3:PutObject` | `InboundFunctionRole` | Resource is the evidence bucket ARN plus `tenants/*/inbound/*`. The `*` is the tenant id and the object name under `inbound/`. The handler writes only keys it builds as `tenants/{tenant_id}/inbound/{sha256}/{uuid}`. |
| `secretsmanager:GetSecretValue` | `InboundFunctionRole` | Resource is `arn:aws:secretsmanager:{region}:{account}:secret:oerf/whatsapp/access_token-*`. The trailing `*` is the Secrets Manager random suffix. The handler reads that one secret for the Meta Graph media download. |
| `states:SendTaskSuccess` | `InboundFunctionRole` | Task-token APIs have no resource type. The action handler does not call them. This role does not send `SendTaskFailure`. |
| `sns:Publish` | `ChannelRouterFunctionRole` | Publishing SMS to a phone number has no SNS resource ARN. SMS should move to `pinpoint-sms-voice-v2` under OERF-116 (Mudita). |
| `dynamodb:ListStreams` | `StreamBroadcasterFunctionRole` | The incident-stream event source calls `ListStreams`, which has no resource type. `DescribeStream`, `GetRecords`, and `GetShardIterator` stay on this table's stream ARN. |
| `social-messaging:SendWhatsAppMessage` | `ChannelRouterFunctionRole` | TODO: when context `whatsapp:phoneNumberId` is unset, no phone-number-id ARN exists at synth, so the resource stays `*`. When the id is set, the statement is `arn:aws:social-messaging:{region}:{account}:phone-number-id/{id}` and this row does not apply. |
| `xray:PutTraceSegments`, `xray:PutTelemetryRecords` | `AgentRuntimeExecutionRole` | X-Ray rejects a resource ARN. The AgentCore runtime enables tracing on this role only when context `agentcore:enabled` is true. |
| `ecr:GetAuthorizationToken` | `AgentRuntimeExecutionRole` | ECR authorization has no resource type. Image pull actions stay on the asset repository ARN. Present only when context `agentcore:enabled` is true. |
| `xray:GetSamplingRules`, `xray:GetSamplingTargets` | `AgentRuntimeExecutionRole` | X-Ray sampling APIs have no resource type. The AgentCore runtime adds them when tracing is enabled. |
| `cloudwatch:PutMetricData` | `AgentRuntimeExecutionRole` | `PutMetricData` has no resource type. The AgentCore runtime adds it when tracing is enabled. |
| `xray:PutTraceSegments`, `xray:PutTelemetryRecords` | role of `oerf-waba-event-destination` | `tracing=ACTIVE` on that function. Present only when context `whatsapp:wabaId` is set. X-Ray rejects a resource ARN. |
| `logs:CreateLogDelivery`, `logs:GetLogDelivery`, `logs:UpdateLogDelivery`, `logs:DeleteLogDelivery`, `logs:ListLogDeliveries`, `logs:PutResourcePolicy`, `logs:DescribeResourcePolicies`, `logs:DescribeLogGroups` | `OerfColdChainStateMachineRole`, `EngagePartyStateMachineRole` | Step Functions log delivery has no resource type. Both machines log at `ERROR` and do not include execution data. |
| `xray:PutTraceSegments`, `xray:PutTelemetryRecords`, `xray:GetSamplingRules`, `xray:GetSamplingTargets` | `EngagePartyStateMachineRole` | Tracing on `oerf-engage-party`. X-Ray rejects a resource ARN. |
| `xray:PutTraceSegments`, `xray:PutTelemetryRecords`, `xray:GetSamplingRules`, `xray:GetSamplingTargets` | `OerfColdChainStateMachineRole` | Tracing on `oerf-cold-chain`. X-Ray rejects a resource ARN. |
| `logs:DescribeLogGroups` | `AgentRuntimeExecutionRole` | Resource is `arn:aws:logs:{region}:{account}:log-group:*`. The runtime adds it when context `agentcore:enabled` is true. |
| `logs:DescribeLogStreams`, `logs:CreateLogGroup` | `AgentRuntimeExecutionRole` | Resource is `arn:aws:logs:{region}:{account}:log-group:/aws/bedrock-agentcore/runtimes/*`. Present only when context `agentcore:enabled` is true. |
| `logs:CreateLogStream`, `logs:PutLogEvents` | `AgentRuntimeExecutionRole` | Resource is `arn:aws:logs:{region}:{account}:log-group:/aws/bedrock-agentcore/runtimes/*:log-stream:*`. The application log group stays on its own ARN. Present only when context `agentcore:enabled` is true. |
| `xray:PutTraceSegments`, `xray:PutTelemetryRecords` | `DashboardQueryFunctionRole`, `DashboardActionFunctionRole` | `tracing=ACTIVE` on the dashboard functions. Present when the dashboard stack is synthesized. X-Ray rejects a resource ARN. |
| `sts:AssumeRole` | `OerfGitHubDeployRole` | Resource is `arn:aws:iam::{account}:role/cdk-hnb659fds-*-{account}-{region}`. The `*` is the CDK bootstrap role name (`deploy`, `file-publishing`, `image-publishing`, `lookup`) so one statement can name them. It also matches `cfn-exec-role`. That role trusts only `cloudformation.amazonaws.com`, so this statement does not let GitHub assume it. `cloudformation:DescribeStacks` and `ssm:GetParameter` on `/cdk-bootstrap/hnb659fds/version` stay on the bootstrap deploy role. The CLI calls them after `AssumeRole` (`DeploymentActionRole` sids `CliPermissions` and `ReadVersion` in the [bootstrap template](https://github.com/aws/aws-cdk-cli/blob/main/packages/aws-cdk/lib/api/bootstrap/bootstrap-template.yaml)). |
| `iam:CreateOpenIDConnectProvider`, `iam:DeleteOpenIDConnectProvider`, `iam:UpdateOpenIDConnectProviderThumbprint`, `iam:AddClientIDToOpenIDConnectProvider`, `iam:RemoveClientIDFromOpenIDConnectProvider` | CDK `OpenIdConnectProvider` custom-resource role | CDK legacy custom resource that manages the GitHub OIDC provider; migrating to the native resource would replace the provider during the deploy-role change; deferred to post-MVP. |
